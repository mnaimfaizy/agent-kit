Seventh **beta** on the `1.0.0` line, classed **Major**, for one required new permission on the review Caller. It adds a third First-class flow, **Review response**, which answers a pull request's code review, and is off until you turn it on. QA evidence now stands alone. A fix scenario runs at the merge-base as well as the head, and each scenario gets one of five results. A web scenario gets a **Storyboard** image and, if its plan asks for video, an annotated MP4. `manual-qa` ships its own drivers for the `web` and `api` surfaces, and `orchestrate` now detects the harness it runs on.

### Consumer action

- **Review Caller permission (required).** Give your review Caller's job (the one that `uses:` `agent-review-reusable.yml`) a job-level `permissions:` block with `contents: read`, `issues: read`, `pull-requests: write` and `actions: write`. Do this even in manual mode, or the review stops running ([#130](https://github.com/mnaimfaizy/agent-kit/issues/130)). `examples/plan-implement-review-caller.yml` shows the block.
- **Upgrade as always.** Move the `uses:` pins and the Kit-owned paths together. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.7 upgrade --tag v1.0.0-beta.7
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.

- **QA Stack commands:** on a run with a fix scenario, `up`, `migrate` and `seed` also run from a merge-base worktree, and `down` must free whatever `up` took. Update them together with `manual-qa` if `up` assumes the developer's own folder.
- **Older QA Reports:** a report written by an older `manual-qa`, with a bare `FAIL` and no headline, no longer passes `report.mjs read`. Re-grade it before posting it with this version. A bare `FAIL` becomes `FAIL: regression`, or `FAIL: pre-existing` with its evidence, and the report gains its headline.

### Review response: a third First-class flow

- **The skill.** `address-pr-review` answers the unresolved review threads on an open pull request: `fixed` (one commit per finding), `addressed` or `declined` ([#127](https://github.com/mnaimfaizy/agent-kit/issues/127)). It shows every reply first and posts only after you confirm. It never force-pushes, never pushes from a fork, and never merges.
- **The workflow.** `agent-review-response-reusable.yml` runs one Response round when a pull request gets the `agent:address-review` label ([#128](https://github.com/mnaimfaizy/agent-kit/issues/128), [#129](https://github.com/mnaimfaizy/agent-kit/issues/129)). Auto mode, the **Handoff**, starts one round after a review that left findings ([#130](https://github.com/mnaimfaizy/agent-kit/issues/130)). It is on only with `CLAUDE_REVIEW_RESPONSE_MODE` set to `auto`; the default stays manual.
- **Guide and Caller.** See [docs/review-response.md](docs/review-response.md), and `examples/review-response-caller.yml` with CLI support ([#131](https://github.com/mnaimfaizy/agent-kit/issues/131)). The plan-implement-review example Caller carries the handoff inputs, commented out ([#224](https://github.com/mnaimfaizy/agent-kit/issues/224)).

### QA evidence that stands alone (spec [#231](https://github.com/mnaimfaizy/agent-kit/issues/231))

- **Plan format 3.** A scenario can name its evidence with **Capture:** (`screenshot`, `video`, `transcript` or `none`). It is marked as a fix with **Expected before:** ([#233](https://github.com/mnaimfaizy/agent-kit/issues/233)).
- **A shipped web driver.** `web.mjs` runs a JSON step sequence in Playwright's Chromium. At each step it saves a still, the step's subject and its text, and with `--video` it keeps a recording per Session. It withholds any still that would show a sign-in value. Playwright and ffmpeg are optional; the readiness notes say what a run loses without each ([#232](https://github.com/mnaimfaizy/agent-kit/issues/232), [ADR 0008](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.7/docs/adr/0008-manual-qa-ships-a-playwright-driver-for-the-web-surface.md)).
- **Before and After, five results.** On a `stack` target, each fix scenario runs first at the merge-base. The stack is then stopped, and the head runs on the same stack. Each row is graded **PASS**, **FAIL: regression**, **FAIL: pre-existing**, **Not proven** or **left for a person**, under one of three headlines that `report.mjs` checks ([#234](https://github.com/mnaimfaizy/agent-kit/issues/234)).
- **Storyboards.** `s<n>-storyboard.png` is one image per scenario. A band at the top names the scenario, the result, each side's expected and observed text, and the commits. Below it come numbered steps, with Before beside After. A caption privacy check refuses to write it if it would show a sign-in value or a token ([#235](https://github.com/mnaimfaizy/agent-kit/issues/235)).
- **Annotated MP4s.** For `Capture: video`, `s<n>.mp4` plays Before beside After, with the band, each step's caption and a timing line overlaid ([#236](https://github.com/mnaimfaizy/agent-kit/issues/236)).
- **Stricter uploads.** Only finished Storyboards and MP4s, `api` logs, and plain stills for a scenario with no Storyboard are offered. `report.mjs evidence` refuses anything else and names the rule. A failed run still uploads no media ([#237](https://github.com/mnaimfaizy/agent-kit/issues/237)).

### `manual-qa` and `qa-plan`

- **An `api` driver.** `http.mjs` runs a request sequence on Node's built-in `fetch`, with no dependency, and writes a redacted evidence log ([#208](https://github.com/mnaimfaizy/agent-kit/issues/208)).
- **Plan fields and checks.**
  - A scenario can carry its own **Surface:**, from plan format 2 ([#203](https://github.com/mnaimfaizy/agent-kit/issues/203), [ADR 0007](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.7/docs/adr/0007-a-qa-plan-scenario-carries-its-own-surface.md)), and an **Observes:** line that `manual-qa` checks each driver against ([#204](https://github.com/mnaimfaizy/agent-kit/issues/204)).
  - A promise that only reading can check becomes a `Review:` box ([#205](https://github.com/mnaimfaizy/agent-kit/issues/205)), and `report.mjs read --plan` checks that Follow-ups lists each one left open ([#222](https://github.com/mnaimfaizy/agent-kit/issues/222)).
  - The plan check reports shell commands in Setup and Steps ([#199](https://github.com/mnaimfaizy/agent-kit/issues/199), [#215](https://github.com/mnaimfaizy/agent-kit/issues/215)), and a first-word value that a mark stuck to it makes invalid ([#201](https://github.com/mnaimfaizy/agent-kit/issues/201)).
- **qa-plan's own checks.** `qa-plan` asks whether a test could prove a promise before making it a manual scenario ([#206](https://github.com/mnaimfaizy/agent-kit/issues/206)). It no longer counts a suite that replaces a real service with a double as proof ([#192](https://github.com/mnaimfaizy/agent-kit/issues/192)). An **Expected result:** never assumes a default read from source ([#200](https://github.com/mnaimfaizy/agent-kit/issues/200)). And it warns about a QA Report comment for an older head ([#207](https://github.com/mnaimfaizy/agent-kit/issues/207)).
- **Run checks and reports.** The run readiness check asks nothing of a plan with no scenarios ([#221](https://github.com/mnaimfaizy/agent-kit/issues/221)), and says what each answer to the surface question changes ([#223](https://github.com/mnaimfaizy/agent-kit/issues/223)). A QA Report can carry a **Run deviations:** line ([#202](https://github.com/mnaimfaizy/agent-kit/issues/202)).

### `orchestrate`: harness detection

- At step 1, `orchestrate` finds the **Harness** it runs on and shows its **Support Level**. The Dispatch Plan says what that level means for the run ([#194](https://github.com/mnaimfaizy/agent-kit/issues/194), [ADR 0006](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.7/docs/adr/0006-orchestrate-runs-on-a-detected-harness.md)).

### Fixed

- `orchestrate` has Executors for Cursor, so a Cursor run no longer invents them ([#189](https://github.com/mnaimfaizy/agent-kit/issues/189)).
- `orchestrate`, `qa-plan` and `manual-qa` check which copy of themselves runs before anything else, so an older user-level copy defers to the repository's own copy ([#190](https://github.com/mnaimfaizy/agent-kit/issues/190)).
- `orchestrate` no longer calls a pull request Ready to Merge before Agent-kit's review workflow has reviewed its head ([#191](https://github.com/mnaimfaizy/agent-kit/issues/191)).
- `http.mjs` no longer redacts every `deleted` in the evidence log after a cookie is removed ([#213](https://github.com/mnaimfaizy/agent-kit/issues/213)).

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.7` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
