Sixth **beta** on the `1.0.0` line, classed **Minor**. `orchestrate` gains a QA stage that runs `qa-plan` and `manual-qa` on each finished branch before it reaches Ready to Merge. `manual-qa` now saves a local screenshot at every scenario's expected result, so a QA Report carries evidence by default. The QA config reader now reports three out-of-subset YAML inputs it used to read silently. No reusable-workflow inputs, secrets or permissions changed.

### Consumer action

- **Upgrade as always.** Move the `uses:` pins and the Kit-owned paths together. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.6 upgrade --tag v1.0.0-beta.6
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.

- **`orchestrate` with a QA config:** a repository with a `qa.config.{yml,yaml,json}` and no `ready_to_merge.qa` in `orchestrate.config.*` is asked about QA at the start of its next run. Set `ready_to_merge.qa: none` to keep the old behaviour without being asked, or `report` to turn the QA stage on.
- **`manual-qa` reports:** a QA Report written by an older run, with a bare `none` on a PASS or FAIL row, no longer passes `report.mjs read`, so it cannot be posted until that Evidence cell gives a reason (`none: <reason>`).
- **`qa.config.yml`:** a config that read before may now stop `adapter.mjs check` with a problem on its line. Quote a value that contains `: `, move a `#` comment out of a one-line flow collection, or delete a list item that is only a comment.

### `orchestrate`: QA stage

- **QA Delegations.** With `ready_to_merge.qa: report`, each building Delegation that needs QA gets a **QA Delegation** of its own (`d<issue>-qa`) in the Dispatch Plan ([#179](https://github.com/mnaimfaizy/agent-kit/issues/179)). It starts once the branch's report is verified, CI is green, review is settled and the branch merges cleanly, and runs `qa-plan` and `manual-qa` on that one head. Ready to Merge needs its result. Any later push, a review fix or a conflict merge included, voids the result and the new head is QA'd again.
- **What comes to you.** Delivering the QA Plan is always a Decision Request carrying the draft. A FAIL comes to you with its evidence (send it back, run QA again, or accept it), and scenarios left for a person come to you to run or waive. Posting the QA Report is a routine write you can approve for the run.
- **Scope fence.** The fence now binds every change on the branch, including fixes prompted by a reviewer, CI or an automated fixer. A change outside it is a Decision Request first.

### `manual-qa`: evidence by default

- **Local capture needs no question.** Every scenario that runs to a PASS or FAIL gets a screenshot at its expected result in the gitignored `working_dir`, a FAIL also gets one where it diverged, and a multi-session or timing-dependent scenario gets a recording, or before-and-after screenshots ([#167](https://github.com/mnaimfaizy/agent-kit/issues/167)).
- **`none` needs a reason.** A PASS or FAIL row with no file says why, as `none: <reason>`, and `report.mjs read` refuses one that does not.
- **Uploading is unchanged.** `run.evidence.upload` still defaults to `none`, files are still picked one by one, a failed run's media is never offered, and a public repository still gets a warning first. The baseline capture rules (no filled password field, no one-time code, no sign-in value) bind every capture.

### Fixed: QA config reader

- `adapter.mjs` in `qa-plan` and `manual-qa` now reports, with its line, a ` #` comment inside a one-line flow collection and a `: ` inside an unquoted value, and reads a comment-only list item as an item with no value ([#174](https://github.com/mnaimfaizy/agent-kit/issues/174)). Quoted values, URLs and trailing comments read as before.
