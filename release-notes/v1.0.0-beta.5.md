Fifth **beta** on the `1.0.0` line, classed **Minor**. It adds two Portable skills: `plain-prose`, which edits text a person will read into plain, specific sentences, and `orchestrate`, which runs a set of issues or a whole spec through other agent sessions. Everything is additive. Both skills are User-scope and user-invoked, add new Kit-owned paths, and change no existing skill. No reusable-workflow inputs, secrets or permissions changed.

### Consumer action

- **None required.** Upgrade the `uses:` pins and the Kit-owned paths together, as always. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.5 upgrade --tag v1.0.0-beta.5
  ```

  It replaces the Kit-owned paths (now including `.claude/skills/plain-prose/` and `.claude/skills/orchestrate/`), rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.

- **To use either skill outside a kit-adopting repository,** install it from this tag, for example `npx skills add mnaimfaizy/agent-kit#v1.0.0-beta.5 --skill orchestrate -g`. See [`docs/install-skills.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.5/docs/install-skills.md).

### `orchestrate`

- **Chief of Staff for a set of issues.** `/orchestrate #12 #34` makes your session the **Chief of Staff**. It analyses each issue by its triage role, shows one **Dispatch Plan** (each **Delegation**'s scope, Executor, model and wave), and after your "go" hands each Delegation to an **Executor**: a separate Live Session, a headless run, or a sub-agent. It relays every **Decision Request** to you, keeps a board and **Activity Logs** in a gitignored run folder, checks every report against git, the tracker and CI, finds merge conflicts between finished branches, and ends with the **Ready to Merge** list and a merge order. `--status` prints the board and `--resume <run>` continues a run.
- **Spec mode.** `/orchestrate --spec <n>` runs a whole spec. Sub-issues become Delegations in waves that follow their blocking edges. A spec written as phases runs each phase in the order written, and the skill offers to publish the phases as tickets first. A spec with neither gets a Decision Request to break it down. The Dispatch Plan asks how the work lands: one local integration branch with one pull request at the end, or one pull request per ticket with later waves parked until you merge their blockers.
- **Authority.** It never merges, force-pushes, changes repository settings, or destroys a branch, worktree or checkpoint without your yes. A Delegation may push its own branch, open its own pull request and reply on its own review; every other write in your name is drafted for your approval. An integration branch is never pushed without your yes.
- **Config.** The skill names no repository command. Your routes, re-gate commands, models, limits, label mapping and Ready to Merge rules come from `orchestrate.config.yml` at the repository root. The skill's `config.mjs` names every unknown key and wrong shape with its line, in YAML or JSON, and stops the run. With no config, it asks. Start from [`examples/orchestrate.config.yml`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.5/examples/orchestrate.config.yml), and read the guide, [`docs/orchestrate.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.5/docs/orchestrate.md). Why it is a core plus a config: [ADR 0004](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.5/docs/adr/0004-orchestrate-is-a-core-plus-a-config.md).
- **Not verified: a live run.** No `/orchestrate` run on real issues was done for this release. The config reader's suite and the contract tests cover the skill, and its harness reference marks the items not confirmed in a harness's documentation as "check before use". The spec that built it (#169) was run by hand-started sessions, not by the skill. Treat your first run as a trial and report what you find.

### `plain-prose`

- `/plain-prose` on a file or pasted text edits it into plain, specific sentences: a pull request body, a README, an ADR, release notes. It rewords and deletes, and adds no fact: where a sentence needs a figure, a source or a definition the text lacks, it flags the sentence for the author. It leaves code, quotes, glossary terms, template headings and agent-read files (`AGENTS.md`, `CLAUDE.md`, skill files) untouched.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.5` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
