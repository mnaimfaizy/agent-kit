Eighth **beta** on the `1.0.0` line, classed **Major**, for two contract breaks: the Stage settings are renamed, and the kit's reviewer posts every finding as an inline thread through a new runtime script. `orchestrate` can now run autonomously, ruling on a fixed set of decisions itself, keeps a heartbeat while you are away, runs QA from the brief in an autonomous run, and re-checks each Ready to Merge row against the default branch as it now is. The `code-review` skill reports a Docs-impact finding, and eight **Pattern guides** describe agent workflows to set up in your own repository.

### Consumer action

- **Rename your repository variables (required).** Each Stage's settings are now named `CLAUDE_<STAGE>_<SETTING>` ([#246](https://github.com/mnaimfaizy/agent-kit/issues/246), [ADR 0009](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0009-stage-settings-resolve-in-the-caller.md)). The old names are dropped, with no fallback:

  | Old                            | New                            |
  | ------------------------------ | ------------------------------ |
  | `CLAUDE_PIPELINE_ENABLED`      | `CLAUDE_AGENT_FLOW_ENABLED`    |
  | `CLAUDE_MODEL_PLAN`            | `CLAUDE_PLAN_MODEL`            |
  | `CLAUDE_MODEL_IMPLEMENT`       | `CLAUDE_IMPLEMENT_MODEL`       |
  | `CLAUDE_MODEL_REVIEW`          | `CLAUDE_REVIEW_MODEL`          |
  | `CLAUDE_MODEL_REVIEW_RESPONSE` | `CLAUDE_REVIEW_RESPONSE_MODEL` |
  | `CLAUDE_MODEL_AUDIT`           | `CLAUDE_SECURITY_AUDIT_MODEL`  |

  **The Agent flow (plan → implement → review) stays off until `CLAUDE_AGENT_FLOW_ENABLED` is set to `true`.** Once your Callers read the new names, `doctor` warns about each old variable still set and names the new one. For each old variable you set, copy its value to the new name, then delete the old one:

  ```bash
  gh variable set CLAUDE_AGENT_FLOW_ENABLED --body true
  gh variable delete CLAUDE_PIPELINE_ENABLED
  ```

- **Copy the runtime files from the same tag (required).** The review workflow now runs `.github/agent-runtime/review-threads.mjs`. Without it, the review fails before the agent runs; with an older copy, a review that uses `### Checked` or `### Fixed` fails its Review report check. `agent-kit upgrade` copies it.
- **Upgrade as always.** Move the `uses:` pins and the Kit-owned paths together. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.8 upgrade --tag v1.0.0-beta.8
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit. Apply the `examples/` diff: it moves every Caller to the new names and passes `effort`.

- **Review response with a formatter (if your checks run prettier).** Add `/review-response-brief.md` and `/review-response.json` to the formatter's ignore file. The kit writes its brief to the workspace root, and it is not prettier-clean, so `prettier --check .` would fail every round.

### Every review finding is a thread

- The kit's reviewer posts every finding as an inline review thread, on all three axes and nits included, so the Review responder answers all of them ([#264](https://github.com/mnaimfaizy/agent-kit/issues/264), [ADR 0011](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0011-every-review-finding-is-a-thread.md)). A finding about an unchanged line or a missing file is anchored on the changed line that causes it, and names the real location in its first sentence.
- The tracking comment becomes the **Review report**: an index linking each thread under the three axes. What the reviewer checked goes under a `### Checked` line, and on re-review the findings the head has fixed go under `### Fixed`.
- A trusted script, `review-threads.mjs`, gives the reviewer its open threads and their latest Verdicts. After the review, it fails the job when a report entry links no thread of the reviewer's, so the Handoff does not start, and posts the reviewer's replies to Verdicts it disputes. On re-review the reviewer posts no duplicate thread.

### Per-Stage model, effort and Kill switch

- Every Stage (plan, implement, review, Review response, security audit) reads its own model and effort. A model resolves as `CLAUDE_<STAGE>_MODEL`, then `CLAUDE_MODEL`, then `claude-opus-5-5`. Effort resolves as `CLAUDE_<STAGE>_EFFORT`, then `CLAUDE_EFFORT`, then nothing: with no value, `--effort` is left off and the model's own default applies.
- All five reusable workflows take a new `effort` input. The run fails before the agent starts if `effort` is anything but `low`, `medium`, `high`, `xhigh` or `max`, or if `model` is not a plain model id, and the error names the input.
- Inside the Agent flow, `CLAUDE_PLAN_ENABLED`, `CLAUDE_IMPLEMENT_ENABLED` and `CLAUDE_REVIEW_ENABLED` each turn one Stage off when set to `false`; unset means on. `CLAUDE_SECURITY_AUDIT_ENABLED` and `CLAUDE_REVIEW_RESPONSE_ENABLED` are unchanged, and Review response is not under the master switch.

### `orchestrate`

- **Autonomous runs.** Answer the Dispatch Plan with `go autonomous` and the Chief of Staff answers a fixed set of Decision Requests itself as **Rulings** ([#274](https://github.com/mnaimfaizy/agent-kit/issues/274), [ADR 0008](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0008-orchestrate-may-rule-under-review.md)). Each Ruling needs evidence that can be checked later and goes into the run's **Ruling Ledger**. Everything else still comes to you, and nothing is Ready to Merge until you have upheld or overturned its Rulings in the **Ruling Review**. A plain `go` run is unchanged.
- **QA from the brief.** In a `go autonomous` run on a `target: stack` plan, the QA session follows `qa-plan` and then `manual-qa` from its brief, and you type neither command ([#289](https://github.com/mnaimfaizy/agent-kit/issues/289), [ADR 0013](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0013-in-an-autonomous-orchestrate-run-the-qa-skills-run-from-the-brief.md)). Each QA skill lists what replaces each step that waits on you. A `target: url` plan stays typed by you. In every run, the QA readiness question is asked once, in the Dispatch Plan, and `qa-plan` reuses the answers with the new `--answers <file>`.
- **A heartbeat while you are away.** Every harness's `await` pairs its own event with a heartbeat that re-arms itself, every 10 minutes by default, and checks every Delegation, its checks and its review run on each wake-up ([#279](https://github.com/mnaimfaizy/agent-kit/issues/279)). A Delegation's report says `**Final:**`, and the Chief of Staff verifies only a final report.
- **Ready to Merge, re-checked.** Before it lists a row at close-out, and whenever you come back with `--status`, `--resume` or "merged <pr>", `orchestrate` reads the pull request's `mergeStateStatus` and checks, test-merges it against the default branch's current tip, and re-gates it if the tip moved ([#288](https://github.com/mnaimfaizy/agent-kit/issues/288)). A `BEHIND` row, or a failed re-gate, is a Decision Request.

### `code-review`: Docs-impact finding

- The Standards pass names each doc page and line a diff leaves saying the old thing, as a finding that does not block ([#257](https://github.com/mnaimfaizy/agent-kit/issues/257), [ADR 0010](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0010-doc-facts-are-generated-and-renames-are-registered.md)). It reads your repository's Docs map if you have one (a file `AGENTS.md` or `CLAUDE.md` names, or a `docs-map.md`), and otherwise searches the docs. No setup.

### Pattern guides

- Eight pages under `docs/patterns/`, each with a skeleton under `examples/patterns/`, describe an agent workflow you set up and adapt in your own repository ([ADR 0012](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/adr/0012-pattern-guides-are-docs-a-consumer-adapts.md)): the [commit pipeline](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/commit-pipeline.md), the [pull request pipeline](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/pr-pipeline.md), [tiered quality gates](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/tiered-quality-gates.md), the [merge train](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/merge-train.md), [sub-agent sync across harnesses](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/sub-agent-sync.md), a [registry of external skills](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/external-skills-registry.md), the [instruction layout](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/instruction-layout.md) and the [planning chain](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/patterns/planning-chain.md). They are documentation, not Kit-owned paths: `init` does not copy them and `upgrade` never overwrites them.

### Review response

- A new optional `format_commands` input names a Caller-owned formatter, such as `npx prettier --write .`, that the agent may run on its edits before the checks. It runs in the same sandbox as `verify_commands`.
- The staged checks end with one line naming the exit code and the last command that failed, so a long output cut short still says which check broke.

### Fixed

- Review response no longer fails every round at **Check git configuration after setup**: the step's own input matched the variables it refuses (affects v1.0.0-beta.7).
- Review response's `verify_commands` run in a sandbox where `uv run` cannot write its cache. [review-response.md](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.8/docs/review-response.md) and the example Caller now say to call installed tools, not cache-writing wrappers.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.8` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
