First **beta** on the `1.0.0` line. The CLI now covers adoption end to end (`init`, `upgrade`, `doctor`), and the plan, implement, review and audit flows are running in a Consumer repository other than this one. No reusable-workflow inputs, secrets or permissions changed.

### Consumer action

- **None required.** Upgrade the `uses:` pins and the Kit-owned paths together, as always.
- **Recommended:** let the CLI do both. From a clean branch in your repository (your current pins must be `v1.0.0-alpha.11` or later):

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.1 upgrade --tag v1.0.0-beta.1
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit. After a Dependabot pin bump, add `--from <old tag>`.

### Added

- **`agent-kit init --tag <vX>`** adopts Agent-kit in a new Consumer:
  - copies the Kit-owned paths;
  - writes a Caller for each flow you pick: `pipeline` (plan, implement, review) and `audit`, with your Allowlist logins, tag, default branch, verify commands and a setup preset filled in;
  - writes the Threat pack skeleton and, if you have none, a `.github/dependabot.yml`;
  - prints the secrets, labels, Claude GitHub App, rulesets and Kill switch steps as `gh` commands to run yourself.

  It refuses to overwrite an existing Caller or Kit-owned path unless you pass `--force`, which lists the uncommitted changes it would discard. It never overwrites an existing Threat pack file. Kit-owned paths that already match the tag are left alone, so you can add the second flow later.
- **`agent-kit upgrade --tag <vY>`** moves a Consumer to another tag. It works out every change and checks every refusal before writing anything, and asks before it writes.
- **Threat pack skeletons** in `examples/threat-pack/` (`threat-model.md`, `findings-ledger.md`).

### Changed

- The example Callers are named `agent-pipeline` and `security-audit`, matching the files `init` writes.
- `doctor`, `init` and `upgrade` print invisible and bidirectional formatting characters as `\uXXXX`, so a file name or message can't read differently from what it is.

### Fixed

- **Scheduled audits failing with "Empty report"** ([#92](https://github.com/mnaimfaizy/agent-kit/issues/92)). The agent could start a background subagent and end its turn waiting for it, which ends a headless run. Every agent now runs subagents and commands in the foreground only, and denies the scheduling and background tools no run needs. One side effect: in the implementer, a Bash command that reaches its timeout now stops instead of carrying on in the background.
- **Runs failing when GitHub's release CDN returns errors on the Bun download** ([#86](https://github.com/mnaimfaizy/agent-kit/issues/86)). Each reusable workflow now installs the pinned Bun itself, from the npm registry first and the GitHub release second, each checked against a pinned SHA-256.
- **A misleading git-configuration error after an implement run that failed before the agent started** ([#83](https://github.com/mnaimfaizy/agent-kit/issues/83)).

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.1` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
