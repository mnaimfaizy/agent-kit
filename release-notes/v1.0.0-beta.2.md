Second **beta** on the `1.0.0` line. Agent-kit's Portable skills can now be installed one at a time, without adopting the kit, and every skill says where it works. No reusable-workflow inputs, secrets or permissions changed.

### Consumer action

- **None required.** Upgrade the `uses:` pins and the Kit-owned paths together, as always. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.2 upgrade --tag v1.0.0-beta.2
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.
- **Don't install the kit's skills with `npx skills` in a repository that adopts the kit.** A project install replaces the Kit-owned skill folder with a link, which `upgrade` refuses. `doctor` now reports it and prints the fix.

### Added

- **Install individual skills** ([`docs/install-skills.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.2/docs/install-skills.md)). If you want one skill and not the rest of the kit, install it from a release tag:

  ```bash
  npx skills add mnaimfaizy/agent-kit#v1.0.0-beta.2 --skill code-review -g
  ```

  The page has the command for each skill. `security-audit` installs into a repository (no `-g`) and needs a Threat pack there, and `security-response` installs together with `security-finding-triage`. Upgrading means re-running the command with the new tag. Installs without a tag are not supported.
- **Every Portable skill declares its scope** in its `SKILL.md` frontmatter as `metadata.agent-kit-scope`:
  - `user`: works from your own skills directory in any repository;
  - `repo`: needs supporting files in the repository. This is `security-audit` only.

  [`docs/releases.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.2/docs/releases.md) now treats a move from User-scope to Repo-scope, or a new required supporting file, as Major.

### Changed

- `security-audit` stops before any work when there is no Threat pack, and says it is a Repo-scope skill that needs one. The automated audit flow is unaffected. Its delivery rule now says the reusable workflow files the draft advisory in CI, and that you file it yourself when you run the audit by hand.
- `security-response` says it requires `security-finding-triage`, since its `triage` mode runs it.
- `instruction-drift-audit` works from your own skills directory as well as from inside a repository. In its commands, `<skill>` is now the skill folder's absolute path, quoted.

### Fixed

- **`doctor` and linked Kit-owned paths.** Before, a Windows junction (what `npx skills` makes) passed as matching, and a symlink stopped the whole Kit-owned paths check with a raw git error. Now each linked path fails in plain words and the other paths are still compared. At a skill folder linked by `npx skills`, `doctor` prints the fix: remove the link and `.agents/skills/<name>/`, then run `upgrade --tag <tag> --force`.
- `init`, `upgrade` and `doctor` no longer fail now and then with `ENOTEMPTY` while removing their temporary tag repository.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.2` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
