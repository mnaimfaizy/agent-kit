Fourteenth **beta** on the `1.0.0` line, classed **Major**: the repository variables that set up each Stage are renamed from `CLAUDE_` to `AGENT_KIT_`. It also adds a `harness` setting per Stage (Claude Code is still the only harness that runs one) and provider-named, optional model secrets.

### Consumer action

- **The Agent flow stays off until you set `AGENT_KIT_AGENT_FLOW_ENABLED`.** The new example Callers read only the new variable names, so copying them turns plan, implement and review off until `AGENT_KIT_AGENT_FLOW_ENABLED` is `true`. The security audit, Review response and the Deep scan likewise stay off until `AGENT_KIT_SECURITY_AUDIT_ENABLED`, `AGENT_KIT_REVIEW_RESPONSE_ENABLED` and `AGENT_KIT_DEEP_SCAN_ENABLED` are `true`. A Stage you had turned off with `false` runs again unless you set its new variable to `false` too.
- **Renamed and removed names (required).** These changed in v1.0.0-beta.14, and the old names no longer work, with no fallback. Replace each one in your Callers, repository variables and settings:

  | Kind     | Old                              | New                                 |

  | variable | `CLAUDE_AGENT_FLOW_ENABLED`      | `AGENT_KIT_AGENT_FLOW_ENABLED`      |

  That applies once you replace your Callers: the new example Callers read only the new names, with no fallback. A Caller you have not replaced keeps reading the old names against the new tag, because the reusable workflows' inputs are unchanged. So when you copy the new Callers, set each new variable to the old one's value, then delete the old one once no Caller reads it. `CLAUDE_CODE_VERSION` and the `CLAUDE_CODE_*` environment keep their names. `agent-kit doctor` names every old variable still set.

- **A Scan recipe whose image is musl Linux, such as Alpine, is now refused by `agent-kit deep-scan`: name a glibc image such as a Debian or Ubuntu one, or name no image to run on the kit's Harness image.** The Deep scan now runs from the kit's Harness image, pinned by digest, with no npm install at scan time.

- A Scan recipe that names no image now gets Node 24 LTS and its npm on that Harness image.

- **Everything else needs nothing.** Upgrade the `uses:` pins and the Kit-owned paths together, as always. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.14 upgrade --tag v1.0.0-beta.14
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.

### A harness per Stage

- Each Stage takes a new optional `harness` input: `AGENT_KIT_<STAGE>_HARNESS`, then `AGENT_KIT_HARNESS`, then `claude-code` in the example Callers. The accepted names are `claude-code`, `codex`, `gemini`, `opencode`, `cursor` and `custom:<name>`. Only `claude-code` runs a Stage in this release; any other value fails the run before the agent starts ([#457](https://github.com/mnaimfaizy/agent-kit/issues/457)).
- An empty model is filled in by the reusable workflow with the harness's default (`claude-opus-5-5` on `claude-code`).

### Model secrets

- `agent-kit doctor` asks for the Anthropic API key first for the Deep scan, and fails when both of its credentials are set.
- Every model secret input is optional and named for its provider. Every example Caller job passes all of them, so changing harness later needs no Caller edit. A run fails, naming the credential, when its harness's credential was not passed.
- The plan, implement, review, Review response and security audit Stages accept an `ANTHROPIC_API_KEY` in place of the subscription token. With both passed, the token is used, so a repository that already holds an API key for something else keeps its billing.
- The Deep scan Caller now passes both `AGENT_KIT_DEEP_SCAN_ANTHROPIC_API_KEY` and `AGENT_KIT_DEEP_SCAN_CLAUDE_CODE_OAUTH_TOKEN`: set exactly one of them.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.14` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
