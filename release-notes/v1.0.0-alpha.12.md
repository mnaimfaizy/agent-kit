First release of the **`@mnaimfaizy/agent-kit` npm CLI**, built from the adoption feedback in [#67](https://github.com/mnaimfaizy/agent-kit/issues/67). No reusable-workflow inputs, secrets or permissions changed; upgrade the `uses:` pins and the Kit-owned paths together, as always.

### Consumer action

- **None required.**
- **Recommended:** add `doctor --ci` as a check on pin-bump pull requests, so a Dependabot bump that moves the pins without re-copying the Kit-owned paths fails instead of passing quietly. See `docs/getting-started.md`, "Check the setup with doctor":

  ```yaml
  - run: npx --yes @mnaimfaizy/agent-kit@1.0.0-alpha.12 doctor --ci
  ```

### Added

- **`agent-kit doctor`**, a read-only check of a Consumer against the tag its Callers pin:
  - Kit-owned paths match the tag;
  - the `uses:` pins agree;
  - the secrets and variables the Callers pass are set;
  - Trigger labels exist;
  - the Claude GitHub App is installed;
  - rulesets block what `docs/repository-hardening.md` recommends.

  Each result is fail, warn or skip; a skipped check is never counted as passed. `--strict` turns warnings into failures. `--ci` checks only files and pins, with no GitHub login.

  It runs git without hooks or configured filter commands, prints fix commands only for names that pass a strict allowlist, and escapes control characters in its output.
- **npm publishing from the tag.** The package version equals the tag, and it is published with trusted publishing and provenance, behind a protected `npm` environment, with no stored token. This first version is a one-time manual publish by the maintainer; later versions carry provenance.

`init` and `upgrade` follow in a later release. Tags before `v1.0.0-alpha.11` have no `kit-owned-paths.txt`, and the CLI refuses them.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-alpha.12` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
