Fourth **beta** on the `1.0.0` line, classed **Minor**. QA Plans can now create accounts mid-run and sign two people in at once, and `explainer` can draw a sequence across a system as a stepped stage and catches brief claims that the source or the platform contradicts. Everything is additive: `explainer`'s new `STAGE.md` is read only for the new stage and stepper shapes, so static pages and existing installs keep working, and `render --write`'s new refusal over a commented YAML config is a skill-internal script change that the skills handle by asking you. The QA Plan format stays `format=1`. No reusable-workflow inputs, secrets or permissions changed.

### Consumer action

- **None required.** Upgrade the `uses:` pins and the Kit-owned paths together, as always. From a clean branch in your repository:

  ```bash
  npx @mnaimfaizy/agent-kit@1.0.0-beta.4 upgrade --tag v1.0.0-beta.4
  ```

  It replaces the Kit-owned paths, rewrites the Agent-kit pins, prints the `examples/` diff for you to apply to your Callers by hand, and runs the `doctor --ci` checks. It commits nothing; review `git diff` and commit.

- **If you installed `qa-plan`, `manual-qa` or `explainer` with `npx skills`,** reinstall from this tag, for example `npx skills add mnaimfaizy/agent-kit#v1.0.0-beta.4 --skill qa-plan -g`. See [`docs/install-skills.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.4/docs/install-skills.md).

### QA Plans (`qa-plan` and `manual-qa`)

- **Scenario accounts.** A scenario can create an account during the run with `` **Creates:** `temp-user` ``, and a later scenario signs in as it with ``**Signs in as:** `temp-user` (created in S1)``. The plan checker refuses a sign-in as an account no earlier scenario creates. If the creating scenario does not pass, `manual-qa` leaves every scenario that depends on it for a person, and says why. A Scenario account's values stay in the conversation; the QA Report lists its id only.
- **Sessions.** A scenario that needs two people signed in at once carries ``**Sessions:** A = `user`, B = `admin` `` in place of **Signs in as:**, and each step starts `In session A,` (or `In A,`). `manual-qa` runs it only on a driver that keeps each session's cookies and storage apart (an isolated browser context per session, or a different browser for each), never tabs in one profile; without one, it leaves the scenario for a person. An older runner refuses such a scenario as lacking **Signs in as:**, so upgrade `qa-plan` and `manual-qa` together.
  - **Not verified: the live two-browser run.** No `manual-qa` run of a two-session scenario against a real app with two isolated drivers was done for this release. The behaviour is covered by the plan checker's tests and the skills' contract tests only.
- **`--answers <file>`.** `two-point.mjs` takes the answers given in chat as a JSON file, so the two-point run works with no `qa.config.yml` and writes none, even when you declined to save the answers.
- **Commented configs are no longer rewritten silently.** `adapter.mjs render --write` now refuses to write over a YAML config that has comments, exits 3 and names the lines. The skill asks you, and drops the comments with `--write --drop-comments` only if you agree. A preview, a JSON config and a new file behave as before.
- **Which shell runs a suite.** [`ADAPTER.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.4/.claude/skills/qa-plan/ADAPTER.md#which-shell-runs-command) now says `plan.suites[].command` runs under `cmd.exe` on Windows and `/bin/sh` on Linux and macOS, from the repository root, and how to write one command for both.
- **First-word values.** The plan format now states how the checker reads **Target:**, **Surface:** and **Signs in as:** (up to the first space or punctuation, with backticks and `*` / `_` at either end dropped). A role id such as `team_admin` now matches its **Roles:** entry instead of being read as `teamadmin`.

### `explainer`

- **Page shape and the system stage.** Step 1 now picks a page shape and the brief states it: a **system stage** for a sequence that crosses two or more components, a **scene stepper** for one that stays inside one, and **static** for a structure. A brief that names no shape is static, and the static shape's rules are unchanged. The new [`STAGE.md`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.4/.claude/skills/explainer/STAGE.md) guide holds the stage contract and design rules, the builder runs and reports _Stage checks_ for those shapes, and [`examples/system-stage.html`](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.4/.claude/skills/explainer/examples/system-stage.html) shows the shape.
- **Brief errors.** When the source or a **platform rule** (a browser, protocol or runtime rule, such as HttpOnly cookies being unreadable by page script) contradicts a brief's claim, the page renders what actually happens and the Builder Report lists it under _Contradictions found_ as a brief error. A platform rule the builder could not cite is marked **unverified**, in the report and on the page. The builder never edits the brief; the briefer fixes it and rebuilds, or accepts the corrected rendering.
- **Screenshot review.** When the builder can drive a headless browser, it screenshots the first screen and each important state at desktop and phone width, in light and dark, fixes what reads poorly, and says exactly what it looked at. Without one, it measures and says the visual review was not possible, as before.
- **Concept-level collision check.** The grounding guide's collision check now searches by concept, not only by constant name: sibling names (`<STEM>_TTL*`, `<STEM>_EXPIRE_*`, …, case-insensitively), inline literals and every call site that sets the quantity. Two differently named constants for one quantity are no longer reported as one value.

### `doctor`

- The `release-tag-push` check no longer warns on a workflow whose `actions/checkout` step sets `ssh-key:`, since `git push origin` then uses that deploy key. The [hardening guide](https://github.com/mnaimfaizy/agent-kit/blob/v1.0.0-beta.4/docs/repository-hardening.md#personal-account-repositories-pushing-release-tags) shows that route.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-beta.4` and copy every path in `kit-owned-paths.txt` from the same tag. See `docs/adopt.md`.
