Security pre-release for [GHSA-h5h6-4v46-73f9](https://github.com/mnaimfaizy/agent-kit/security/advisories/GHSA-h5h6-4v46-73f9). The implementer's Bash guard now judges every command, so the `git add`, `git commit`, and `git rm` grants can no longer read a runner file or a secret from the agent's environment into a commit message or a pull request. Upgrade the `uses:` pins and the copied files together.

### Consumer action

- **Required:** re-copy `.github/agent-runtime/` from this tag. Implement checks before the agent starts that the staged Bash guard refuses a commit that reads a file.

### Security

- The guard refuses git options that read a file (`-F`/`--file`, `-t`/`--template`, `--pathspec-from-file`, and the abbreviations git accepts), git's global options, and an environment assignment before git.
- It refuses shell expansion and input redirection (`$`, backticks, `<`) outside single quotes in any implementer Bash command. The implementer is told to write commit messages with `-m` and single-quoted text.
- Code run through `extra_allowed_tools` is outside this check, as before: grant such entries only for issue authors you trust.

See `CHANGELOG.md` for the full list. Pin reusable workflows with `uses: <owner>/agent-kit/.github/workflows/<file>@v1.0.0-alpha.10` and copy skills plus `.github/agent-runtime/`, `.github/security-audit/`, and `.github/agent-pipeline/` from the same tag. See `docs/adopt.md`.
